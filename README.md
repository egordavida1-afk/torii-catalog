# Тории — каталог фильмов и сериалов

Next.js 14 (App Router) + Prisma + PostgreSQL. Проект рассчитан на GitHub + Vercel, а база — на Neon или другой PostgreSQL.

В проекте уже есть:

- фильмы и сериалы как два типа контента;
- блок «Новинки», отдельные блоки «Фильмы» и «Сериалы»;
- поиск по названию/описанию и фильтр по типу и жанру;
- жанры, которые создаются и удаляются из админки;
- отдельный фон для каждого тайтла;
- для фильма — одна видеоссылка, для сериала — сезоны и серии;
- просмотр закрыт для незарегистрированных пользователей;
- регистрация с паролем от 8 символов, сессионные токены хранятся только в виде SHA-256 хеша;
- отдельный доступ в админку;
- базовая защита от перебора логина и случайного удаления, проверки ID/типа/URL/чисел на сервере;
- `.env` больше не хранится в репозитории.

## Локальный запуск

Нужен Node.js 20+ и PostgreSQL.

1. Скопируй `.env.example` в `.env.local` и заполни переменные.
2. Примени миграцию:

```bash
npm install
npm run db:migrate
npm run seed
```

3. Запусти сайт:

```bash
npm run dev
```

Открой `http://localhost:3000`.

## Переменные окружения

```env
DATABASE_URL="postgresql://..."
DIRECT_URL="postgresql://..."
ADMIN_USER="admin"
ADMIN_PASSWORD="свой-длинный-пароль"
ADMIN_SECRET="случайная-строка-минимум-24-символа"
```

Для Neon удобно использовать пуллированное соединение как `DATABASE_URL` и прямое как `DIRECT_URL`. Prisma официально описывает такую схему подключения для приложений с Neon.

## Админка

`/admin` защищён отдельной cookie-сессией.

В админке можно:

- создать фильм или сериал;
- назначить постер, фон, год, статус и жанры;
- создать новые жанры;
- изменить данные существующего тайтла;
- у фильма задать одну ссылку на видео;
- у сериала создать сезоны и серии;
- удалить контент после подтверждения.

Перед созданием контентных связей сервер перепроверяет родительский объект. Для URL разрешены только `http` и `https`, числа проверяются по диапазонам, а серверные actions повторно проверяют права администратора.

## Регистрация и просмотр

Каталог можно просматривать без аккаунта, но страница просмотра `/anime/[slug]` отправит незарегистрированного посетителя на `/login`. После регистрации пользователь получает 30-дневную сессию. Пароль не хранится в открытом виде: используется `scrypt` с солью.

## GitHub

```bash

git commit -m "Prepare movie and series catalog"
git branch -M main
```

Важно: `.env`, `.env.local` и база данных не попадут в Git благодаря `.gitignore`. В GitHub нельзя класть реальные `DATABASE_URL`, `DIRECT_URL`, `ADMIN_PASSWORD` или `ADMIN_SECRET`.

## Бесплатный деплой

Для этого проекта удобнее всего связка **GitHub → Vercel → Neon**.

Vercel имеет бесплатный Hobby-план и умеет подключать Git-репозиторий с автоматическими деплоями. У проекта будет бесплатный адрес вида `имя-проекта.vercel.app`.

Neon предоставляет бесплатный план PostgreSQL, подходящий для небольших проектов/прототипов; актуальные лимиты лучше смотреть в консоли провайдера.

### 1. Создай базу Neon

Создай PostgreSQL-проект в Neon и возьми connection string. Для Prisma оставь две переменные, `DATABASE_URL` и `DIRECT_URL`, как в `.env.example`. Neon документирует обе схемы подключения и рекомендует pooled URL для приложения и direct URL для миграций. citeturn634112search0

### 2. Загрузи проект на GitHub

Создай пустой репозиторий, затем выполни команды из раздела GitHub выше.

### 3. Импортируй репозиторий в Vercel

В Vercel выбери **Add New → Project → Import Git Repository**, выбери свой GitHub-репозиторий и нажми Deploy.

В **Settings → Environment Variables** добавь:

```text
DATABASE_URL
DIRECT_URL
ADMIN_USER
ADMIN_PASSWORD
ADMIN_SECRET
```

После этого сделай redeploy.

### 4. Примени миграцию и демо-данные

Один раз с компьютера, используя production-строки подключения, выполни:

```bash
npx prisma migrate deploy
npm run seed
```

После этого сайт и админка используют удалённую PostgreSQL-базу.

## Про бесплатный домен

Есть важное различие между **бесплатным адресом сайта** и **настоящим доменным именем**.

Бесплатно получить можно адрес `project.vercel.app` или аналогичный сервисный поддомен. Настоящий домен вроде `mysite.com` обычно нужно зарегистрировать/оплатить отдельно; не стоит рассчитывать на сомнительные сервисы «вечных бесплатных .com/.ru».

Для этого проекта самый простой вариант без оплаты домена — оставить адрес Vercel `project.vercel.app`. Vercel позиционирует Hobby как бесплатный план, а платный Pro отдельно содержит «Free custom domain» среди возможностей плана; поэтому не путай бесплатный Vercel-поддомен с бесплатной регистрацией собственного домена.

GitHub Pages для этой версии проекта не подходит как основной хостинг: статический экспорт Next.js не поддерживает cookies, middleware и другую серверную логику, а этот проект использует серверные действия, регистрацию и PostgreSQL.

## Видеоконтент

Админка принимает URL на YouTube или прямой URL видео. Сам проект не хранит видеофайлы внутри Git. Для реального проекта видео лучше держать в отдельном объектном хранилище/CDN, а в базе хранить только ссылку. Next.js отдельно предупреждает, что файлы, появляющиеся во время работы приложения, не являются постоянными статическими asset'ами; для постоянного хранения рекомендуется стороннее хранилище.

Размещай только тот контент, на который у тебя есть необходимые права.
